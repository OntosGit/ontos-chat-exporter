# ONTOS · Археология незавершённых архитектур · Первый исполняемый контур

## Что реализовано

Локальная база SQLite (FTS5) для импорта ChatGPT-разговоров из официального ZIP (`conversations*.json`), одиночного JSON экспорта ONTOS Chat Exporter или JSON-файла `conversations.json`. При импорте выделяется *основная видимая ветка*: пользовательские и обычные ответы ассистента; внутренние каналы и сообщения инструментов не используются как намерения пользователя.

База хранит неизменяемые версии содержимого сообщений и привязку каждого импортированного снимка к версиям. Повтор той же выгрузки обнаруживается по SHA-256; удаление/редактирование реплики в новой выгрузке не затирает историческую версию. Поиск работает по актуальному снимку разговора. Если источник передаёт `update_time`, более старый снимок не может вытеснить более новый.

Команда `discover` составляет список **кандидатных фрагментов речи пользователя** по прозрачным лексическим признакам. Она не утверждает, что кандидат является действующим поручением, и не добавляет карточки в Todoist. Ассистентский текст не превращается в владельческое поручение. При повторном анализе IDs кандидатов сохраняются.

Команды `record`, `attach`, `link`, `show` поддерживают ручную проверку и восстановление генеалогии архитектуры через несколько сообщений и ссылки на внешние артефакты. Точная ссылка на исходный разговор доступна там, где ID соответствует ожидаемому формату. Прямых сетевых запросов, платного AI API и изменений в GitHub/Todoist нет.

## Запуск на Windows

Нужен Python 3.10+ с SQLite FTS5. В каталоге `ontos-chat-exporter`:

```powershell
py -3 tools/ontos_memory.py --db private/ontos-memory.sqlite3 init
py -3 tools/ontos_memory.py --db private/ontos-memory.sqlite3 import "$env:USERPROFILE\Downloads\chatgpt-export.zip"
py -3 tools/ontos_memory.py --db private/ontos-memory.sqlite3 stats
py -3 tools/ontos_memory.py --db private/ontos-memory.sqlite3 search "архитектура"
py -3 tools/ontos_memory.py --db private/ontos-memory.sqlite3 discover --limit 30
```

Путь к архиву в команде замените на реальный. Для одиночного разговора укажите путь к JSON вместо ZIP. `discover` вернёт `candidate_id`, `revision_id`, URL и выдержку. Результаты доступны только на компьютере, с которого вы запустили программу.

### Превращение кандидатного фрагмента в архитектуру

После содержательной сверки с более поздними чатами, `ONTOS.NODE`, GitHub и Todoist:

```powershell
py -3 tools/ontos_memory.py --db private/ontos-memory.sqlite3 record --id ARCH-0001 --title "Источники спроса" --candidate C-PASTE_REAL_ID --state researching
py -3 tools/ontos_memory.py --db private/ontos-memory.sqlite3 attach --id ARCH-0001 --candidate C-ANOTHER_REAL_ID --relation development
py -3 tools/ontos_memory.py --db private/ontos-memory.sqlite3 link --id ARCH-0001 --kind github --url https://github.com/OntosGit/ONTOS.NODE
py -3 tools/ontos_memory.py --db private/ontos-memory.sqlite3 show ARCH-0001
```

**Не считать любое совпадение по слову «создать» незавершённой задачей.** Чат хранит исходный смысл; GitHub и Drive показывают действительные результаты, Todoist содержит только реально нужный следующий переход. В `ONTOS.NODE` переносится проверенная абстрактная карта, без полного приватного текста. Исходный JSON и SQLite остаются приватными.

## Каноническое согласование

Пилот **не** объявляет локальную базу вторым каноном: она индексирует первичный материал и хранит локальные исследовательские записи. Перед публикацией нового узла в `ONTOS.NODE` исполнитель проверяет актуальную версию графа и похожие предметные записи. Если задача уже есть, добавляет свидетельство в неё, а не дублирует задачу. При отсутствии права на запись сохраняет локальную кандидатуру.

Исключены автоматическое изменение Todoist, публикация полных чатов в GitHub, распознавание скрытых альтернативных веток как принятых решений и декларация AI-семантики там, где работает только FTS + лексические правила.

## Дальнейшее расширение без переустройства основания

1. Подключаемый локальный эмбеддинг-индекс для семантического поиска поверх сообщений (не замена устойчивых идентификаторов и исходников).
2. Работа Codex с `discover` как с очередью кандидатов: читать первичные фрагменты, собирать хронологию, различать принятое решение и гипотезу. Записывать машинную рекомендацию отдельно от подтверждённой архитектуры.
3. Инкрементальная загрузка следующих экспортов; при большом ZIP рассматривать потоковый JSON-парсер. Текущий пилот ограничивает отдельный JSON 256 МиБ и суммарный распакованный размер выбранных файлов ZIP 512 МиБ.
4. Передавать подтверждённые записи в существующий `ONTOS.NODE` с обратным чтением. Ссылку в Todoist создавать только при наличии отдельного фактического действия и после проверки дублей.
5. Для новой реальной задачи измерять время до верного следующего действия и количество ложных восстановлений. Увеличение числа найденных кандидатов не является KPI.

## Безопасность

- `private/`, `*.sqlite3`, `*.db` и пользовательские `.json`/`.zip` запрещено коммитить в публичный репозиторий.
- Запускайте анализ только на своей машине. Сырой ZIP может содержать закрытые переписки и метаданные.
- Примерные тесты синтетические, никаких настоящих сообщений в тестах нет.
- В публичной ветке GitHub хранится **только код, тесты и документация**.
